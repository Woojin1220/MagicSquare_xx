## STEP 1 — Mom Test 요약

### 페르소나
4×4 부분 마방진(빈칸 2개)을 **손으로/코드로** 다루는 **학습자**.

### Mom Test 증거 (과거·구체)
1. 「특정 행·열부터 합을 맞춤」
2. 「맞다고 생각하고 넘어갔어」
3. 「채점결과」→「처음부터 다시」→「10분」→「반대 대각선」

### 표면 문제 (잘못된 정의)
「4×4 마방진 **검증/풀이 프로그램**(또는 PyQt **완성 앱**, ECB **설계 완성**)을 만든다」

### 진짜 문제 (한 문장)
**4×4 부분 마방진(빈칸 2개, 10선 합 34)을 손으로 맞출 때 행·열·대각선을 맞추고 `/` 네 칸 합을 34와 비교했다고 생각했는데도, 제출 후 채점에서 틀렸고, 처음부터 다시 하며 반대 대각선 `/` 합이 깨져 있음을 알게 되어 그 문제에 약 10분을 더 썼다.**

### 인터뷰 상세 (Q&A 요약)

| # | 질문 요지 | 답변 |
|---|-----------|------|
| 1 | 맨 처음 손으로 한 일 | 특정 행·열부터 합을 맞춤 |
| 2 | 행·열 다음 | 대각선을 봤어 |
| 3 | `\`와 `/` | 둘 다 |
| 4 | 문제 종료 | 맞다고 생각하고 넘어감 |
| 5 | 틀림 인지 계기 | 채점 결과 |
| 6 | 채점 후 행동 | 처음부터 다시 |
| 7 | 추가 시간 | 10분 |
| 8 | 틀린 것 | 대각선의 합 |
| 9 | 어느 대각선 | 반대 대각선 `/` |
| 10 | 채점 전 `/` 검증 | 네 칸 숫자를 전부 더해 34와 비교 |
| 11 | 빈칸에 최종 숫자 여부 | **미응답** (인터뷰 종료) |

## STEP 3 — 세션 3 주제 (Mom Test 기반)

**4×4 부분 마방진(빈칸 2개)을 풀 때 행·열만 맞추고 “맞다”고 넘기기 쉬운데, 채점 후에야 `/` 같은 줄이 깨져 있음을 알게 되는 일을 줄이기 위해, 10선(합 34) 판정을 빠짐없이·재현 가능하게 만드는 워크플로(Rule·Command·Test Loop)를 세션 3에서 고정한다.**

### R-G-I-O

| | |
|---|---|
| **Role** | 4×4 부분 마방진 과제를 받은 학습자 — 손 계산 후 **10선=34** 검증, 실패 시 **어느 줄**인지 파악 |
| **Goal** | 빈칸 2개 채운 뒤 **10선**이 모두 34인지 판정; 실패 시 **깨진 줄**(특히 `/`) 식별 |
| **Input** | 4×4 정수 격자 (`0`=빈칸 **2개**, 그 외 1~16, 중복 없음) |
| **Output** | 10선 합 vs 34, 실패 줄 종류·인덱스, (선택) 빈칸 좌표·후보 판정 |

### 성공 기준 (Mom Test 연결)

| ID | 기준 | Mom Test 연결 |
|----|------|---------------|
| SC-1 | **10선 합 전부** 계산·검증 (`\`·`/` 포함) | 「특정 행·열부터 합을 맞춤」→ 행·열만으로 완료 처리 금지 |
| SC-2 | 10선 중 하나라도 ≠34 → **실패 + 줄 식별** | 「맞다고 생각하고 넘어갔어」+ 「반대 대각선」 |
| SC-3 | 동일 유형에서 **원인 줄 특정 1분 이내** | 「10분」+ 「처음부터 다시」→ 채점·전면 재시작 시간 단축 |

## STEP 5 — 문제 정의 (PRD 연결)

### 핵심 질문
> **"4×4 격자에서 빈칸 2개를 채운 결과가 부분 마방진 조건(10선=34)을 만족하는가?"**

### 판정 규칙
1. 격자 크기 4×4, 값 0 또는 1~16
2. 0(빈칸) **정확히 2개**
3. 1~16 **중복 없음** (빈칸 제외)
4. **10선** 각각 합 = 34

### 실패 시 반환 (개념)
- E001: 잘못된 크기
- E002: 빈칸 개수 ≠ 2
- E003: 범위/중복 위반
- E004: 특정 줄 합 ≠ 34 (줄 종류·인덱스 포함)

### 문제 인식 조건 예시 (슬라이드 연습 · 3개 이상)
1. 10선 중 **어느 한 줄** 합 ≠ 34 (Mom Test: `/` 깨짐)
2. 빈칸 개수 ≠ 2
3. 1~16 **중복** 또는 범위 위반
4. (선택) 빈칸 미채움 상태에서 “완료” 처리
